## Code Review

### High Severity (bugs with wrong runtime behavior)

**1. Deskew angle correction is backwards — `core/doc_reader.py:221-224`**

```python
angle = cv2.minAreaRect(coords)[-1]
# comment says [-90, 0) but OpenCV ≥ 4.5 returns [0, 90)
if angle < -45:          # this branch is never taken
    angle = 90 + angle   # angle is never negative
```

On OpenCV ≥ 4.5, `minAreaRect` returns angles in `[0, 90)`. The `angle < -45` branch never fires. A page with a large tilt (e.g., angle=85) is then rotated by 85°, flipping it sideways. Fix:
```python
if angle > 45:
    angle = angle - 90
```

**2. `existing.unified_value` can be `None`, crashing Pydantic — `core/parser.py:282-283`**

```python
"document": existing.unified_value if existing else "",
```

`existing` can be non-`None` but have `unified_value=None` (field found but not extracted). Pydantic's `dict[str, str]` on `ValidationIssue.values` will reject `None`. Fix: `existing.unified_value or ""`.

**3. Parse-failed required docs are double-counted as missing — `core/agent.py:152`**

When a required doc fails to parse, its `doc_type` becomes `"unknown"`. The present-types set doesn't contain the required type, so a `[missing] police_report` placeholder is appended *in addition* to the already-present parse-failed record. The `determine_status` priority then sees "missing" first and returns `incomplete`, when it should route to `pending` per the architecture spec.

**4. `reply_skipped` mutated in-place on LangGraph state — `core/agent.py:262-266`**

LangGraph state updates should be returned as a new partial dict, not mutated in place. Depending on the LangGraph version, in-place mutation can be silently dropped on merge. If `reply_skipped` never persists as `True`, the routing in `_route_after_reply` (line 277) always sends back to `cross_validate`, and since `reply_count` never increments (no `handle_reply` called), `reply_count < max_rounds` is permanently true → infinite loop.

### Medium Severity (semantic bugs, silent gaps)

**5. Express flag marks all-missing-docs claims as express — `core/agent.py:386-388`**

## 1. Imports: move stdlib to the top

The lazy imports split into two categories — keep one, fix the other.

**Keep lazy** (protecting against missing optional dependencies):

- `google.genai`, `openai`, `transformers`, `torch`, `PIL`, `qwen_vl_utils` in `llm_adapters.py` — split between requirements files by design

**Move to top** (stdlib has no install cost):
- `core/agent.py:32` — `import json` inside `_load_field_schemas()`

## 2. Naming

**Rename for clarity:**

| Current | Better | Why |
|---|---|---|
| `_sha256` | `_hash_file` | Callers want "a content hash", not "SHA-256 specifically" |
| `_express_eligible` | `_is_express_eligible` | Bool-returning functions should read as a predicate |

| `parse_reply` | `extract_reply_fields` | The function does extraction + trust override, not just parsing |

**Inconsistency in `target_fields` vs `field_schemas` vs `schemas`:**

`ClaimState` calls it `field_schemas`, `handle_reply` uses `field_schemas`, but all the `read()` methods use `target_fields`. Pick one and use it everywhere. `schemas` is the shortest and the type already says `list[FieldSchema]`.

## 3. Too many try/except

**`call_vlm` has a redundant dual-except** — `core/doc_reader.py:127-130`:

```python
except ParseFailedError as exc:
    last_exc = exc
except Exception as exc:
    last_exc = exc
```

`ParseFailedError` is a subclass of `Exception`. Both branches do identical things. Collapse to:
```python
except Exception as exc:
    last_exc = exc
```

**The parse-fail `DocRecord` construction is copy-pasted three times** — `PDFReader.read`, `ImageReader.read`, `TextReader.read` each have:

```python
except ParseFailedError as exc:
    return DocRecord(
        file_name=Path(file_path).name,
        doc_type="unknown",
        doc_role="other",
        source_trust="document",
        parse_status="parse_failed",
        status_reason=str(exc),
        content_hash=content_hash,
        raw_text=...,  # varies
    )
```

Extract onto `BaseDocReader`:
```python
def _failed_record(self, file_path: str, exc: Exception, content_hash: str | None = None, raw_text: str | None = None) -> DocRecord:
    return DocRecord(
        file_name=Path(file_path).name,
        doc_type="unknown",
        doc_role="other",
        source_trust="document",
        parse_status="parse_failed",
        status_reason=str(exc),
        content_hash=content_hash,
        raw_text=raw_text,
    )
```

Each reader's except block becomes one line: `return self._failed_record(file_path, exc, content_hash, raw_text)`.

## 4. Overengineered design

**`DocReaderFactory` is a Java-ism**

A class with a single `@staticmethod` is just a namespaced function. In Python, a module-level function is cleaner:

```python
# instead of DocReaderFactory.get_reader(path)
def get_doc_reader(file_path: str) -> BaseDocReader: ...
```

**`BaseDocReader.read` should be `@abstractmethod`**

The current pattern:
```python
def read(self, ...) -> DocRecord:  # pragma: no cover
    raise NotImplementedError
```

`# pragma: no cover` on an intentionally abstract method is a smell. This is what ABCs exist for:

```python
from abc import ABC, abstractmethod

class BaseDocReader(ABC):
    @abstractmethod
    def read(self, file_path: str, schemas: list[FieldSchema], client: BaseLLMClient) -> DocRecord: ...
```

**`_load_pdf_threshold()` reads `settings.yaml` on every single PDF parse**

Every call to `PDFReader.read` opens and parses the YAML file. The threshold never changes at runtime. Either cache it at module level:

```python
_PDF_TEXT_THRESHOLD: int | None = None

def _pdf_text_threshold() -> int:
    global _PDF_TEXT_THRESHOLD
    if _PDF_TEXT_THRESHOLD is None:
        _PDF_TEXT_THRESHOLD = yaml.safe_load(...)...
    return _PDF_TEXT_THRESHOLD
```

Or (simpler) pass it as a constructor arg to `PDFReader`.

**Stateless services stuffed into LangGraph state**

`ClaimState` contains `llm_client`, `chatbot`, `workflow_config`, `message_config`, `parser` — none of these change between nodes. Only `claim` and `reply_skipped` are actually stateful. Putting immutable services into graph state:
- Forces every node to unpack things it doesn't use
- Invites LangGraph to attempt serialization of objects (adapters, chatbot) that shouldn't be serialized

Since `ClaimAgent` already owns these as `self.*`, the node functions could close over them instead:

```python
def _build_graph(self):
    # capture self in closures — nodes become simple, state stays minimal
    def parse_documents(state):
        return node_parse_documents(state, self.field_schemas, self.llm_client)
    ...
```

Or keep the current approach but narrow `ClaimState` to only the values that actually change: `claim` and `reply_skipped`. Constant services live on `self`.

**`determine_status` check at lines 136-156 has two overlapping "required" checks**

Steps 9 and 10 in `determine_status` both check for required docs — `check_required_docs` (step 9) and the `required_complete` `all()` (step 10). The `check_required_docs` call at step 9 can only be reached if all the earlier guards pass, at which point it should be redundant with the `doc_status == "missing"` check at step 1. It's defensive but creates cognitive overhead when reading the function.
